title: Operator-first workflow-aware task view

created: 2026-08-16

Hive task inspection now leads with canonical action, concise known usage and
API-equivalent coverage, and the workflow's primary result. Typed workflow
result semantics decide whether document, worktree, diff, publication, media,
dependency, and supporting evidence applies. Long Markdown results render in a
full-width readable panel with stable anchors, useful outlines, and contained
tables/code.

Semantic `hive-task-workspace` v2 is shared by normal Web HTML, the authenticated
workspace JSON route, and native `hive task TARGET --project NAME --json`.
Strict v1 remains an explicit authenticated audit/mutation compatibility path.
Normal task HTML no longer renders raw attempts, provenance receipts, lifecycle
events, stage chronology, or a newest-file log tail. Genuine error/recovery
states expose the exact attempt receipt's bounded correlated-log reference for
deep diagnosis.

Exact failed/retry sessions are deduplicated into known token totals while
harness, actual provider/model, and launch-bound billing route remain distinct.
A versioned local catalog calculates coverage-labelled API-equivalent estimates
from official first-party OpenAI, Anthropic, and xAI rates without a render-time
network request. Missing evidence remains partial, pending, unavailable, or
unknown; subscription use is never described as zero actual spend.

The canonical Hive operating skill and its checked-in OpenClaw projection now
direct agents to semantic task inspection and receipt-correlated logs, while
forbidding provider-health, quota, credential-validity, invoice, or
provider-observed-billing inferences from the task view.
