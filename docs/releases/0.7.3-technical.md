# Hive 0.7.3 — technical changelog

Source range: `v0.7.2` through `be0e54eb63558675aa7bf07a394125cb51e8679d` (371 commits), followed by the 0.7.3 release-preparation changes described below. The complete source inventory follows the subsystem summary, including test-only changes, dependency updates, internal deletions, and fixes subsequently superseded within this release. The user-facing release notes describe the final behavior rather than every intermediate implementation.

## Web and status

- #1015 introduces the operator task workspace; #1397, #1399, and #1400 refine running state, outcome presentation, task-state preservation, and Kanban layout. #1135 preserves answerable waiting questions. #1306 and #1349 harden web lifecycle and connection ownership.
- #1442 combines installable workflows and modules under Honeycombs. #1443 adds intentional cold-loading presentation and responsive navigation.
- #1444 persists the last successful status payload in a private, atomically replaced JSON snapshot. It validates schema, size, timestamps, project identity, and payload shape before restoring. A restored payload is explicitly cached, cannot authorize actions, and refreshes immediately in the background. Failed writes preserve the previous snapshot. This accelerates restart display; it does not remove the background full scan.
- #1195 makes bounded liveness the default status surface. #1324 selects active stage folders for routine projections and resolves numeric task IDs through folder lookup. #1331 reuses captured active rows for dependency admission. The earlier status/daemon performance series removes repeated task, attempt, configuration, and recovery reads; preserves complete scheduler snapshots; and bounds projection history. #1327 keeps scheduler observations fresh while Patrol scans run.

## Daily activity

- #1407 introduces the host-global daily digest: persisted interval identity, material activity collection, lifecycle and retention, CLI read/refresh/send/prune commands, a web view, and separately scheduled Telegram delivery.
- Readers expose completeness, source gaps, late amendments, and historical task identity. Project filters are views over the same record. Collection and delivery are opt-in; ordinary reads do not collect or send. #1427 preserves delivery ownership during garbage collection.

## Runtime, tasks, and scheduling

- #1375 moves runtime coordination into SQLite. Follow-up fixes address retained checkpoints, task registration scope, hardlinked artifacts, terminal observations, and empty attempt payloads. The task journal becomes the history authority; #1396 derives scheduling from current facts. #1388 reuses validated database state.
- #1425 removes historical format adapters and migration commands. This supersedes earlier cutover recovery work in the range: current releases accept current schemas only, and older retained state needs the documented supervised conversion. See [the conversion guide](../guides/current-format-migration.md).
- Scheduling fixes preserve FIFO/capacity priority, age queued work, drain already accepted work before fresh dispatch, and prune stale recovery before capacity accounting. Markerless retries are requeued atomically and paced; operator retries remain immediately due.
- Recovery handles workflow rewind, runtime replacement, orphaned reviews, rewritten PR heads, interrupted handoffs, and stale attempt custody without fabricating completion. The attempt supervisor sleeps after EOF rather than busy-spinning. TERM-to-KILL escalation checks process identity.
- #1423 makes removal of unwanted tasks use cancellation rather than delivery completion. #1139 makes task inspection workflow-aware. #1208 exposes exact dogfood runtime identity.

## Planning, review, and artifacts

- #994 introduces plan critique before coding execution. The follow-up series preserves reviewed clearance, recovers planner revisions and reviewer capability, validates served model identity, and reassesses gates before escalating to the operator.
- #1112 adds independently reviewed outcome evidence; #1115 feeds retrospective findings back into implementation. Later changes make capture capability reprobes automatic, return implementation defects to execute, and keep optional evidence failures nonblocking. #1441 makes execution pauses actionable.
- Exact-head review settlement handles rewritten drafts, already-merged ancestor commits, repaired heads, failed reviewer retries, and stale validation. Guardrails handle rename/copy paths, Git quoting, control bytes, and explicit diff prefixes. Publisher deduplication uses configured GitHub invocation.
- #1149 and #1150 impose idle-output deadlines on validation and CI. #1370 cools down hosted CI account limits. #1431 escapes babysitter branch arguments and pins the push lease; #1275 stops admitting work after shutdown.

## Patrol

- #1166 unifies ordinary and architecture finding delivery through Patrol Fix; subsequent changes retain progress across restarts and migrate or retire obsolete findings. #1113 replaces scoring/quota machinery with explicit policy, followed by launch-limit and discovery-cap corrections.
- Fixes cover saturated intake, no-job recovery, interrupted stages, clean output after provider limits, stale materialization decisions, external delivery, and periodic architecture sweep scheduling.
- #1295 parks secret-blocked publication; #1403 supplies bundled Betterleaks. #1366 classifies matches in Git diffs, and #1437 removes URL credentials from publication evidence. Publication processes are bounded and hive-state commits serialized.

## Agent runtime and benchmarks

- #998 adds first-class OpenCode through the independently versioned `agent-cli-runtime` component. Hive consumes its published 0.2 line (#1129); this Hive release does not publish another component version.
- OpenCode follow-ups use native runtime state, typed permissions, bounded long session exports, structured provider-limit recovery, prepared startup, and escaped-process cleanup. Pi recovery retains workflow progress, report output, and evidence after rate limits. Claude structured/banner quota classification and Grok HTTP 402/build identity handling are corrected.
- #1420 preserves the ordinary environment for trusted agents; restrictions remain opt-in. #1430 preserves the main Claude reviewer identity across subagents. #1429 permits read-only shell inspection during brainstorm.
- Benchmark fixes bind markers and runtime to the campaign, seal controller/runtime inputs, validate the campaign contract before spend, separate judges from candidates, retain pinned executables and command arguments, and pass successful paid execution output to judging. #1438 stops after planner failure; #1428 preserves runner arguments.

## Packaging, dependencies, and maintenance

- #1406 makes systemd user-service installation replay-safe and removes network-target dependencies. #1000 hardens managed QMD installation. #1106 aligns packaged web security dependency floors.
- Sequel advances to 5.108.0, RuboCop to 1.91.0, Brakeman to 8.0.6, and Docker Buildx setup to 4.3.0. See the inventory for intermediate bumps.
- Internal cleanup removes unused forwarding methods and retired state paths, centralizes authoritative contracts, and improves CLI usage contract ownership. CI changes shorten feedback loops without removing required gates; fixtures isolate operator state and runtime dependencies.

## Release preparation

- Set Hive, root/web lockfiles, installer pins, and generated operating-skill projection to 0.7.3.
- Refresh the reviewed latest-stable baseline to v0.7.2. Verify its signed checksum manifest against the exact release-workflow identity, retain exact asset sizes/digests, and pin its locked runtime dependency closure (the dependency change from v0.7.1 is sqlite3 2.9.6).
- Repair the managed-web release fixture for property-based systemd inspection, require its own health-server probe, and bound transient Betterleaks download retries.
- Align release E2E scanner preparation with ordinary CI and retain scenario diagnostics on failure.
- Publish sectioned user-facing notes in `CHANGELOG.md` and the GitHub release, with this technical inventory as the detailed reference.
- Publication remains gated on the exact merged candidate's ordinary CI, trusted pre-tag artifact proof, and native install checks. This document is a change inventory, not a claim that those release gates have already passed.
