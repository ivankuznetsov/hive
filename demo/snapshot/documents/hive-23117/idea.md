# create-and-ship-a-first-260719-7fa2

Create and ship a first-class natural-language Hive workflow creator AgentSkill, integrated with the repository's existing OpenClaw skill packaging and custom-workflow CLI. A user must be able to tell an agent in ordinary language, for example “Create a three-stage editorial workflow that researches, drafts, and requires approval before publishing,” and have the agent create a valid project-local Hive workflow end to end. Prefer a dedicated triggerable skill such as hive-workflow-creator if the current packaging supports multiple skills; otherwise implement the same clearly named triggerable capability in the existing Hive skill without making the general skill unwieldy. The skill must inspect the target project and existing workflow/templates, translate intent into a workflow id, ordered stages, stage outcomes/artifacts, instructions or reusable skills, agent/model assignments, permissions, automated transitions, and human checkpoints; ask only when a materially different design choice cannot be inferred safely. It should use hive workflow new or hive init --new-workflow as the authoritative scaffold path, then fill the descriptor and stage instruction files rather than inventing an incompatible format. It must validate YAML/frontmatter and loadability through Hive, reject reserved/colliding ids, preserve existing project config and workflows, keep permissions least-privilege, and report exactly what it created plus the next command to create or run a task. Support both existing initialized projects and fresh-project setup. Reuse a built-in template when it genuinely matches, but do not force every request into coding, research, or writing. Include a complete worked example and concise reference material for schema fields, stage design, checkpoint choices, permissions, testing, and common mistakes. Update Hive's bundled OpenClaw skill docs and docs/workflows.md so agents discover the natural-language path as well as the manual CLI path. Ensure install/package flows actually expose the skill to OpenClaw users; do not only add an unreferenced SKILL.md. Add focused skill contract tests, packaging/install tests, YAML validation, and an end-to-end fixture proving a plain-language request can produce a loadable workflow whose first task routes through the expected stages. Run the full test suite, coverage, lint, and skill validation. Start from current main in an isolated worktree and open a PR. Coordinate wording with hive-site task #23116, but do not block implementation on the website PR.
