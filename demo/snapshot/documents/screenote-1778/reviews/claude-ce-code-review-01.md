## Medium
- [x] AUTO-FIX: Login loopback callback can hang the `login` command (`internal/cli/login.go:116,154-181`): <!-- triage: obvious fix — non-blocking send on result channel --> `result` is a size-1 buffered channel and `callbackHandler` sends on every `/callback` hit; a second callback request after the first result is consumed blocks the handler, and the deferred `server.Shutdown` then waits on that blocked handler with no timeout — hanging login indefinitely. Use a non-blocking send (`select { case result <- ...: default: }`). Low likelihood (single redirect in practice) but affects only the new interactive flow and has no timeout guard.
