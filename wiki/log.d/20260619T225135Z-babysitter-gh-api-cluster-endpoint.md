## [2026-06-19T22:51:35Z] babysitter - gh api clustered shorthand endpoint bypass

**Action:** Closed a residual hole in `bin/hive-babysitter-stub-gh`'s `api_endpoint_operand`. A value-taking shorthand clustered behind a boolean — e.g. `gh api -iH 'Accept: x' https://evil.example.com/...`, which gh (pflag) reads as `--include --header 'Accept: x' <url>` — was treated as a plain self-consuming flag, so the parser returned the header value as the endpoint and let the full-URL host slip past the `://` host guard. The parser now mirrors pflag's left-to-right cluster consumption (the same model already used by `auth_status_*` and `short_option_cluster_has_web?`): a value-taking shorthand (`-X -f -F -H -p -q -t`) reached inside a cluster swallows the rest of the cluster as its glued value, or the next argv element when it ends the cluster, so that element is skipped rather than mistaken for the endpoint. `target_operands` (the `repo view` / `pr view|checks|diff` positional parser) is unaffected: it collects *all* positionals and `any?`-matches, so a mis-parsed cluster only adds candidates and cannot drop the real URL.

**Coverage:** Extended `test/unit/babysitter/dry_run_env_test.rb` so `gh api -iH 'Accept: ...' https://evil.example.com/...` is skipped and logged, while a safe relative endpoint behind the same `-iH <value>` cluster (`gh api -iH 'Accept: ...' repos/owner/repo`) still reaches real gh. Verified with `bundle exec ruby -Itest test/unit/babysitter/dry_run_env_test.rb`, `ruby -c bin/hive-babysitter-stub-gh`, and `bundle exec rubocop bin/hive-babysitter-stub-gh test/unit/babysitter/dry_run_env_test.rb`.
