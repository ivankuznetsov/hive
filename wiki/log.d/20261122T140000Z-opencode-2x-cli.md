## 2026-11-22 — Hive runs the OpenCode 2.x CLI

- Symptom: after mise auto-updated OpenCode to 2.2+/2.3.2, every Hive
  OpenCode role failed (the uk-new-companies plan-review adversary, neon).
  2.x removed `run --variant`, `run --dir`, `export`, and
  `OPENCODE_PERMISSION`. The live workaround pinned
  `HIVE_OPENCODE_BIN` to the old 1.19.0 install.
- Change (Hive-side only; agent-cli-runtime untouched):
  `Hive::AgentSupport::OpenCode.run_contract` reads `run --help` once per
  launch. Without `--variant` the effort is folded into
  `--model provider/model#variant` and `--dir` is dropped (spawn cwd is the
  working dir). Inspection uses
  `opencode api --standalone GET /api/session/:id/message/:message_id` and
  `session_export` maps it to the sanitized-export shape, so the result
  parser is unchanged.
- Two 2.x findings, verified on 2.3.2. First, the private server dies under
  the capture's `RLIMIT_FSIZE` because it opens the 1.25 GB session DB, so the
  2.x inspection runs without it (`capture_process_files(fsize_limit:)`).
  Second, `OPENCODE_PERMISSION` is ignored (an env-only deny let a run write a
  file under `--auto`), so the policy now also goes in
  `OPENCODE_CONFIG_CONTENT.permission`, which 2.x enforces.
- MCP isolation parses 2.x `debug config` source lists
  (`mcp.servers`, null `info` on directory sources).
- 1.x keeps its exact argv, export, and limits.
