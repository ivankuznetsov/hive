  the `fix(attachments)` commits on this branch were dropped.
- Correctness reproduced the tombstone-cap defect by execution (rolled-back transaction, no repo
  mutation); testing reproduced both cross-composer directions with a throwaway integration test.
- Clean passes with no findings: project-standards (BEM, enums, service-object shape, MiniTest +
  fixtures, importmap, wiki fragments present and `wiki/log.md` untouched) and api-contract
  (`attachments` always present on detail root and every comment, absent on list rows, MCP golden
  key fixture preserved, Go nil-vs-empty round trip, `url_expires_at` derived from the same
  `MEDIA_TOKEN_EXPIRY` constant as `generates_token_for`).
- Security found no exploitable authorization, ingest, CSRF, or delivery defect. Confirmed sound:
  draft reads are uploader-scoped and a same-project collaborator gets 404; the bearer route
  requires principal + scope + attachment-bound purpose token + `submitted?` + live
  `project_access?`; ingest derives media type from bytes, requires declared/extension agreement,
  and caps dimensions/pixels before a forced full decode; no provider redirect or durable URL;
  the digest email carries no attachment URL.
- Dropped as deliberate plan boundaries: metadata-light list reads omitting `attachments`, and
  media denials collapsing to a single non-enumerating `not_found`.
- Residual risks worth an operator's eye, not filed as findings: media authorization uses the
  denormalized `image_attachments.project_id` rather than the live parent's project (equivalent
  today — nothing relocates a page between projects); the bearer purpose token travels as a query
  parameter, so an external proxy access log would record it (bounded — the token alone grants
  nothing); a valid image with arbitrary trailing bytes is still stored; draft batches of a
  removed member survive to the 24h sweep while still consuming that user's caps; Rack buffers the
  full multipart body before the 20 MB check (bounded in the release image by Thruster's
  `MAX_REQUEST_BODY`); `ImageAttachmentOrphanReconciliationJob` runs its `GROUP BY/HAVING`
  aggregate before `LIMIT 500`, so cost scales with total submitted rows; `RecurringTasks.schedule`
  re-reads and ERB-evaluates `config/recurring.yml` on every `/ready` probe.
- Untested branches noted but not filed: `MAX_DIMENSION` (only `image_pixels_too_large` is
  covered), the `Range:` branch of `BlobStreaming#stream_blob`, and cross-purpose token replay.
