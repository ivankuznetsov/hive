# Versioned execution-plan changes at safe boundaries

Added the shared capability revision service and visible `hive task-capabilities`
command for inert proposals, inspection, acceptance, rejection, per-task QA
exceptions and actual failed security-finding risk acceptance. Mutations compare
exact task identity, active plan version and implementation SHA under the task
lease, and refuse launching, running or unpublished terminal Attempts.
Accepted decisions, plan versions and redacted journal correlation survive
interrupted activation without publishing a second version.

Capture retains unselected verifier templates and bounded verification revision
authority. Human acceptance can declare real checks within that original
authority, including correction of an initially empty QA plan. Current project
policy and candidate generations cannot broaden a task's authority. QA Off
acknowledges the current checks (or `all`), and required QA cannot be waived.
Selected security cannot be removed to bypass an unavailable route.

Planning and review signals create inert proposals; pre-attempt admission can
activate a routine UI addition only under already captured policy. New guidance
remains pending until its real stage executor receives it; late additions expose
the stage to return to and rerun. Explicit installation correction pins a missing
named skill's concrete identity after checking its original actor/runtime/route.
Skill drift between proposal and acceptance rejects the proposal.

Result freshness includes prerequisite checks and capability dependencies,
preserving unrelated identical evidence and the old immutable observations.
Multiple guidance attachments for the same capability are valid at distinct
stages. Retained closed or cancelled tasks remain readable without worktrees
and expose no mutation token. Adoption remains disabled.

A task-specific operator approval can correct selected security that had no
reusable project approval. `--task-approval ID=REFERENCE` proposes only the
already captured actor, scope, targets and resource limits, showing the exact
reference, envelope and digest before acceptance. A captured unavailable route
stays unavailable and blocks finalization while independent dispatch remains
available. Distinct bytes cannot occupy an already accepted plan version, and a
resolved dependency composition error is cleared only after successful graph
validation.

Focused verification passed 282 tests and 1,571 assertions. Current-source
collection covered every executable line in both new library files and every
added executable line in modified library files. The full test suite and
exhaustive coverage were left to the caller's later integration gates.
